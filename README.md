# 차량 예약 조회

카메라로 번호판을 비추면 자동으로 차량번호를 읽고, 바로 아래에 **예약 여부를 신호등**으로 보여주는 확인 페이지입니다.
예약 데이터는 **예약일자 · 예약시간대 · 차량번호**로 DB에 저장되어 있고, 이 페이지는 **조회만** 합니다(예약 등록은 하지 않음).

예약 시간대: **09:00~12:00 / 12:00~15:00 / 15:00~18:00**

- 화면: HTML/CSS/JavaScript (빌드 없음, GitHub Pages로 바로 공개)
- DB: [Supabase](https://supabase.com) (무료 PostgreSQL)
- 번호판 인식: [Tesseract.js](https://tesseract.projectnaptha.com/) 한국어 OCR (기기 안에서 처리, 사진이 외부로 전송되지 않음)
- **오프라인 동작**: 처음 한 번 인터넷으로 열면 앱·인식 파일이 기기에 저장되어, 이후 인터넷 없이 열리고 인식·판정합니다.

## 직원 로그인

확인 앱(`check-7k2q.html`)은 **관리자가 만든 계정**으로 로그인하고, **직원 명단(`staff_emails`)에 있는 사람만** 쓸 수 있습니다.
로그인하지 않았거나 명단에 없으면 예약·정기 차량 데이터를 DB에서 읽을 수 없습니다(화면뿐 아니라 DB 권한으로 막음).

### 처음 설정 (한 번만)
1. Supabase **SQL Editor**에서 `supabase-staff.sql` 실행 (다시 실행해도 안전)
2. **Authentication → Sign In / Providers**(또는 Settings)에서 **새 사용자 가입 허용(Allow new users to sign up)을 끔** — 직원 계정은 관리자만 만들도록
3. GitHub에 `check-7k2q.html`, `app.js`, `style.css`, `sw.js`, `supabase-staff.sql`, `README.md` 업로드

### 직원 추가
1. **Authentication → Users → Add user → Create new user**: 이메일·비밀번호 입력, **Auto Confirm User** 체크
2. **Table Editor → staff_emails → Insert row**: 같은 이메일 입력 (memo에 이름·근무지 등은 선택)
3. 직원에게 이메일·비밀번호와 확인 앱 주소를 알려 줍니다.

### 직원 제외 · 비밀번호 변경
- 제외: `staff_emails`에서 그 줄 삭제 → 그 계정은 다음 동기화(1분 안) 때 자동 로그아웃되고 기기에 저장된 예약도 지워집니다. 계정까지 없애려면 Authentication → Users에서 삭제.
- 비밀번호 잊음: Authentication → Users에서 해당 사용자를 골라 새 비밀번호로 바꿔 알려 줍니다.

### 탭에서 쓰는 방식
- 한 번 로그인하면 계속 로그인된 상태로 유지됩니다 (매번 입력할 필요 없음).
- **인터넷이 끊겨도** 마지막으로 로그인·확인된 계정으로 저장된 예약을 계속 판정합니다. 상단에 `· 오프라인`이 붙습니다.
- 처음 로그인은 인터넷이 연결된 상태에서 해야 합니다.
- 오른쪽 위 **로그아웃**을 두 번 누르면 로그아웃되고, 기기에 저장된 예약도 지워집니다.

## 화면 동작

1. **카메라 켜기** → 번호판이 큰 점선 네모 안 어디든 보이게 비춥니다. 멀리서 작게 보여도 됩니다. 찾은 번호판에 테두리(주황=찾는 중, 초록=읽음)가 생기고, 화면 아래쪽에 번호판이 크게 확대돼 보입니다.
2. 같은 번호가 연속으로 읽히면 확정하고, 영상 바로 아래에 신호가 뜹니다. (현재 시각 기준)
   - 🟢 **초록불 · 입차 가능**: 오늘 예약이고 지금이 예약 시간대
   - 🟡 **노란불**: 오늘 예약이지만 지금은 예약 시간대가 아님 (몇 시간 후 시작 / 종료됨 표시)
   - 🔴 **빨간불**: 오늘 예약이 아님 (다른 날짜 예약이면 그 날짜 표시, 예약이 없으면 뒷번호가 비슷한 오늘 예약 안내)
   - 🔵 **파란불 · 정기 차량**: 사전 예약과 상관없이 출입 가능 (등록 기간 안일 때. 신호 판정에서 가장 먼저 확인)
3. 카메라는 켜진 채로 계속 인식하므로 다음 차량도 바로 확인됩니다.
   - **줌**: 카메라 화면을 두 손가락으로 벌리면 확대, 오므리면 축소 (왼쪽 위 −/+ 버튼, PC는 마우스 휠). 두 번 탭하면 원래 크기. 마지막 배율은 기억됩니다.
   - 카메라가 줌을 지원하는 기기(대부분 안드로이드 Chrome)는 카메라 자체 줌이라 화질이 유지되고, 그 외(아이패드 등)는 화면 확대 방식입니다. 어느 쪽이든 네모 안에 보이는 부분을 읽습니다.
   - 너무 멀어 확대 보기의 글자가 흐리면 두 손가락으로 조금 확대하세요.
4. 인식이 틀리면 번호 칸을 직접 고쳐 **예약 확인**을 누르면 됩니다.
5. 아래 **예약 현황**에서 날짜·시간대별 예약과 오늘 시간대 상태(진행 중 / 대기 / 종료)를 볼 수 있습니다. 1분마다 자동으로 새로 불러옵니다.

## 오프라인 사용 (갤럭시 탭 A 권장 설정)

### 동작 방식
- 예약 판정은 항상 **기기에 저장된 예약**으로 즉시 합니다.
- DB(Supabase)가 연결돼 있으면 인터넷이 될 때 **1분마다** 예약(어제~앞으로)을 받아 기기에 저장합니다.
- 인터넷이 끊기면 마지막으로 받은 예약으로 계속 판정하고, 상단에 `오프라인 · 마지막 동기화 시각`이 표시됩니다.
- 인터넷이 아예 없는 현장은 **예약 파일(CSV)** 을 불러와 쓰면 됩니다. (아래 참고)

### 처음 설치 (한 번만, 인터넷 필요)
1. 갤럭시 탭에서 **Chrome**으로 `https://<아이디>.github.io/plate-reservation/check-7k2q.html` 을 엽니다. (삼성 인터넷보다 Chrome 권장)
2. 10~20초 기다립니다. 이때 앱·인식 파일(약 10MB)이 기기에 저장됩니다.
3. Chrome 메뉴(⋮) → **앱 설치** 또는 **홈 화면에 추가**.
4. 홈 화면 아이콘으로 열고 **카메라 켜기** → 카메라 권한 **허용**.
5. 와이파이를 끄고 아이콘으로 다시 열어 정상 동작하는지 확인합니다.

### 갤럭시 탭 권장 설정
- **설정 → 디스플레이 → 화면 자동 꺼짐**: 길게
- **설정 → 배터리 → 백그라운드 사용 제한**: Chrome을 **제한 안 함**에 추가
- **설정 → 일반 → 날짜 및 시간 → 자동 설정** 켜기 (신호 판정이 기기 시계를 기준으로 하기 때문)
- 충전 케이블을 꽂은 채 거치대에 고정해 쓰는 것을 권장합니다.
- 카메라 상태 표시줄의 `x.x초/회`는 한 번 읽는 데 걸리는 시간입니다. 1초 안팎이면 정상입니다.
- **촬영 거리·각도**: 번호판이 화면 폭의 10% 이상(휴대폰 세로 사진 기준 차 한 대가 화면에 다 들어오는 정도)이면 읽힙니다. 정면에서 좌우 45° 이내가 가장 좋습니다.

### 아이패드·아이폰에서 쓰기
- **iPadOS / iOS 15 이상**을 권장합니다. (설정 → 일반 → 정보 → 소프트웨어 버전)
- 아이패드·아이폰에서는 Chrome도 Safari와 같은 엔진을 쓰므로 **Safari**로 설치하는 것을 권장합니다.
1. **Safari**로 `.../check-7k2q.html`을 열고 10~20초 기다립니다(인식 파일 저장).
2. 주소창 옆 **공유 버튼(□↑) → 홈 화면에 추가**.
3. 홈 화면 아이콘으로 열고 **카메라 켜기** → 카메라 **허용**.
   - 허용 창이 안 뜨거나 거부했다면: **설정 → Safari → 카메라 → 허용**(또는 확인)으로 바꾼 뒤 다시 엽니다.
4. 비행기 모드로 바꾸고 아이콘으로 다시 열어 동작을 확인합니다.
- **홈 화면 아이콘으로 쓰세요.** Safari 탭에서만 쓰면 오래 열지 않을 때 저장된 예약·인식 파일이 지워질 수 있습니다.
- 아이패드는 화면 꺼짐 방지를 위해 **설정 → 디스플레이 및 밝기 → 자동 잠금 → 안 함**을 권장합니다.

### 예약 파일(CSV)로 쓰기
1. 엑셀에서 아래처럼 3열을 만들고 **다른 이름으로 저장 → CSV (쉼표로 분리)** 로 저장합니다. (`예약예시.csv` 참고)

   | 예약일자 | 예약시간 | 차량번호 |
   |---|---|---|
   | 2026-10-20 | 09:00 | 12가3456 |
   | 2026-10-20 | 12:00~15:00 | 123나 4567 |

   - 예약시간은 `09:00`, `9`, `09:00~12:00` 모두 됩니다(시간대 시작 시각으로 맞춤).
   - **정기 차량**은 첫 칸에 `정기`를 쓰고 셋째 칸에 차량번호, 넷째 칸에 메모를 씁니다. 둘째 칸에 날짜를 쓰면 그날까지만 정기 차량으로 인정합니다.

     | 예약일자 | 예약시간 | 차량번호 | 메모 |
     |---|---|---|---|
     | 정기 | | 11가1111 | 관리사무소 |
     | 정기 | 2027-10-31 | 222나3333 | 협력업체 (연간) |
   - 날짜는 `2026-10-20`, `2026.10.20`, `2026/10/20` 모두 됩니다.
2. 파일을 탭으로 옮기고(카톡·USB·구글 드라이브 등), 화면 아래 **예약 파일 (CSV) → 예약 파일 불러오기**.
3. 새 파일을 불러오면 이전 파일 예약은 바뀝니다. DB 예약과 파일 예약은 함께 판정에 쓰입니다.

### 파일을 고쳐서 다시 올릴 때
- `sw.js` 맨 위 `VERSION` 숫자를 하나 올리고(예: `v13` → `v14`), `check-7k2q.html`과 `sw.js` 안의 `?v=13`도 같은 숫자로 바꿔야 기기에 새 버전이 저장됩니다.
- 탭에서 인터넷이 될 때 앱을 두 번 열면 새 버전으로 바뀝니다.

## 정기 차량 관리

정기 차량은 사전 예약과 상관없이 **등록 기간 동안 항상 출입 가능**하며 화면에 🔵 **정기 차량**으로 표시됩니다.

- **이미 DB를 만들어 둔 경우**: Supabase **SQL Editor**에서 `supabase-regular.sql`을 **한 번** 실행하면 `regular_vehicles` 표가 추가됩니다. (`supabase.sql`을 처음부터 실행하는 새 DB는 이미 포함되어 있습니다)
- **등록·해지**: Supabase **Table Editor → regular_vehicles**에서 줄을 추가·삭제합니다.

| 컬럼 | 넣을 값 |
|---|---|
| `plate` | 보기 좋은 번호 (예: `11가 1111`) |
| `plate_key` | 공백 없는 번호 (예: `11가1111`) — 중복 불가 |
| `memo` | 소속·이름 등 (선택) |
| `valid_from` | 정기 시작일 (선택, 비우면 제한 없음) |
| `valid_until` | 정기 종료일 (선택, 비우면 무기한) |

- 기간이 지난 정기 차량은 🔴로 판정되고 "등록 기간이 아니에요"가 함께 표시됩니다.
- 화면 아래 **예약 현황 → 정기 차량** 탭에서 등록된 정기 차량과 기간을 볼 수 있습니다.

## 예약 신청 페이지 (apply.html)

방문자가 휴대폰·PC에서 직접 예약하는 페이지입니다. 신청하면 **바로 확정**되어 확인 앱에 반영됩니다.

- 주소: `https://<아이디>.github.io/plate-reservation/` (맨 앞 주소 = 신청 페이지, `apply.html`로 바로 열어도 됨)
- 입력: 방문 날짜(**관리자가 연 날짜만** 표시 — 아래 **예약 개설 관리** 참고) → 시간대(남은 자리 표시, 마감·지난 시간은 선택 불가) → 차량번호·이름·연락처 → 개인정보 동의
- 완료 화면에 **예약번호**가 나오고, **내 예약 확인** 탭에서 차량번호+연락처로 조회·취소할 수 있습니다.
- **같은 차량은 같은 날짜에 한 번만** 예약할 수 있습니다(시간대·연락처가 달라도, "서울12가3456"처럼 지역명을 붙여도 같은 차량으로 봄). 정원 초과, 정기 차량(예약 불필요)도 자동으로 막습니다. 직원이 CSV·Table Editor로 직접 넣는 예약에는 이 제한이 걸리지 않습니다. 여러 명이 동시에 신청해도 정원을 넘지 않습니다.

### 적용 순서
1. Supabase **SQL Editor**에서 `supabase-apply.sql` 실행 (한 번만, 다시 실행해도 안전)
2. GitHub에 `apply.html`, `apply.css`, `apply.js`와 바뀐 `index.html`, `sw.js`, `README.md`, `supabase-apply.sql` 업로드 (`config.js`는 그대로)

### 개인정보 보관
- 이름·연락처는 `reservation_contacts` 표에 따로 저장되고, 웹페이지(anon 키)로는 읽을 수 없게 잠겨 있습니다.
- 동의 화면에 "방문일로부터 30일 후 삭제"라고 안내하므로, 아래 중 하나로 지워 주세요.
  - 직접: SQL Editor에서 `select public.purge_old_contacts();` 실행 (지운 건수가 나옵니다)
  - 자동: Supabase 대시보드에서 **Cron(pg_cron)** 기능을 켠 뒤 SQL Editor에서 한 번 실행
    ```sql
    select cron.schedule('purge-old-contacts', '0 4 * * *', 'select public.purge_old_contacts()');
    ```
- 동의 문구(수집 항목·목적·보관 기간)는 `apply.html`의 "개인정보 수집·이용 동의" 부분에서 실제 운영 기준에 맞게 고쳐 쓰세요.

- 안내·예약 신청·예약확인증 페이지를 연 횟수를 세어, 관리자 페이지 맨 아래 **접속 현황**에 보여 줍니다(1분마다 갱신).

  - **오늘 페이지뷰 / 방문자**: 페이지를 연 횟수 / 서로 다른 기기 수, 페이지별 내역
  - **오늘 시간대별 그래프**, **최근 7일 추이**
- 저장하는 것: 시각·페이지 이름·기기마다 만든 무작위 번호. **IP·이름·연락처·차량번호는 저장하지 않고**, 90일 지난 기록은 자동으로 지웁니다. 같은 기기가 10초 안에 여러 번 열면 한 번만 셉니다.
- 적용: SQL Editor에서 `supabase-stats.sql` 실행 → `stats.js`와 바뀐 `index.html`·`apply.html`·`pass.html`·`admin-7k2q.html`·`admin.js`·`admin.css` 업로드

## 실시간 예약확인증 (pass.html)

번호판 인식이 안 될 때를 대비해, 방문자가 휴대폰으로 보여 주는 확인증입니다.

- **화면 색 = 확인 앱 신호등과 같은 기준**: 🟢 지금 예약 시간대 · 🟡 오늘 예약이지만 다른 시간대 · 🔴 오늘 예약 없음 · 🔵 정기 차량
- **여는 곳**: 안내 페이지 [실시간 예약확인증] 메뉴, 신청 완료 화면 [실시간 예약확인증 열기], 내 예약 확인의 [확인증] 버튼
- **확인 방법**: 예약 차량은 차량번호 + 예약할 때 쓴 연락처, 정기 차량은 차량번호만 (DB `regular_vehicles`와 연동)
- 한 번 열면 그 휴대폰에 저장돼 다음부터 바로 열립니다. [다른 차량]을 두 번 누르면 지워집니다.
- **위조 방지**: 색은 휴대폰 시계가 아니라 **서버 시각** 기준이라 시계를 바꿔도 달라지지 않습니다. 초 단위 시계와 움직이는 빛줄기가 있어 캡처 화면과 구별됩니다. 30초마다 서버에서 새로 받아 오고, 90초 넘게 못 받으면 "실시간 정보가 아니에요" 경고 띠가 나옵니다.
- **직원 확인 요령**: 시계가 움직이는지, 경고 띠가 없는지, 확인증의 번호와 실제 번호판이 같은지 보세요. 애매하면 확인 앱에 번호를 직접 입력해 확인합니다.
- 직원이 CSV로 넣은 예약(연락처 없음)은 확인증을 열 수 없습니다.

2. GitHub에 `pass.html`, `pass.css`, `pass.js`와 바뀐 `index.html`, `apply.html`, `apply.css`, `apply.js` 업로드 (`config.js`는 그대로)

## 예약 개설 관리 (admin-7k2q.html)

신청 페이지에 어떤 날짜를 열지 관리자가 달력에서 고릅니다. 기간별로 나눠 오픈할 때 씁니다.

- **들어가는 법**: 관리자 페이지 주소(`admin-7k2q.html`)로 직접 엽니다. 안전을 위해 확인 앱·신청 페이지 어디에도 이 페이지로 가는 링크를 두지 않습니다(주소는 관리자만 알고 있기).
- 로그인이 안 되면: ① `supabase-opendates.sql` 실행 여부 ② `staff_emails`에서 그 계정의 `is_admin` 체크를 확인하세요.

- **달력 색**: 초록 = 예약 받는 중 · 주황 = 공개 예정(지정한 일시에 자동으로 열림) · 흰색 = 닫힘. 칸 안에 그날 예약 건수가 나옵니다.
- **① 예약 공개**: 날짜를 눌러 여러 개 고름(또는 **이 달 토·일 모두 선택**) → **바로 공개** 또는 날짜·시간 칸을 눌러 **공개 일시** 지정(칸을 누르면 자동으로 '공개 일시 지정'이 선택됨) → 버튼("바로 열기" 또는 "10/25 10:00 공개 예약")
  - 공개 일시를 정하면 그 시각 **전에는 신청할 수 없고**(신청 페이지에는 흐리게 "10/21(수) 14시 오픈"으로 표시), 그 시각이 되면 새로고침하지 않아도 자동으로 신청할 수 있게 바뀝니다. 공개 일시는 관리자 기기의 시간대(한국) 기준입니다.
  - 예) 11월분을 미리 넣어 두고 공개 일시를 `11/1 10:00`으로 지정하면, 그 시각부터 신청 페이지에 나타납니다.
  - 이미 열린 날을 다시 열면 공개 일시만 바뀝니다.
- **닫기**: 날짜 선택 → **선택한 날 닫기**를 두 번 누름. 신청 페이지에서 바로 사라지지만 **이미 받은 예약은 그대로 유지**됩니다(취소가 필요하면 Table Editor에서).
- **② 시간대별 정원**: 공개와 따로 저장합니다. 날짜를 고르고 09~12시·12~15시·15~18시 칸에 숫자를 넣은 뒤 **정원 저장**. 아직 닫힌(공개 전) 날에도 미리 정해 둘 수 있고, 열기·닫기 버튼은 정원을 바꾸지 않습니다.
  - 기본 정원은 시간대마다 **200**이고, 따로 정하지 않은 날짜는 기본 정원을 씁니다. (기본값 자체는 Table Editor → `slot_capacity`)
  - 여러 날을 함께 고르면 같은 숫자로 한꺼번에 바뀝니다. 날짜마다 다른 칸은 "날짜마다 다름"으로 비어 있고, 비워 두면 그 시간대는 그대로입니다.
  - 0으로 하면 그 시간대는 신청을 받지 않습니다. 이미 받은 예약보다 적게 하면 한 번 더 확인하고, 기존 예약은 유지된 채 추가 신청만 막힙니다.
  - 아래 **앞으로 열려 있는 날짜** 목록에 시간대별 `예약 건수/정원`이 나옵니다.
- 지난 날짜는 고를 수 없습니다. 신청 페이지는 1분마다 날짜 목록을 새로 받아오고, 닫힌 날로 억지로 신청해도 DB에서 거절합니다.
- 처음 설치하면 기존 기간(2026-10-24 ~ 11-22 토·일)이 그대로 열려 있습니다.

### 적용 순서
1. Supabase **SQL Editor**에서 `supabase-apply.sql`을 다시 실행한 뒤 `supabase-opendates.sql` 실행 (`supabase-apply.sql`, `supabase-staff.sql`을 실행한 뒤에. 다시 실행해도 안전)
2. **Table Editor → `staff_emails`** 에서 관리자 계정 줄의 **`is_admin`** 을 체크(true) — 관리자도 직원 명단에 있어야 하고, Authentication에 계정이 있어야 합니다.
3. GitHub에 `admin-7k2q.html`, `admin.js`, `admin.css`, 바뀐 `check-7k2q.html`, `app.js`, `style.css`, `sw.js`, `apply.js`, `apply.html`, `supabase-apply.sql`, `supabase-opendates.sql`, `README.md` 업로드 (`config.js`는 그대로)
4. 관리자 주소로 로그인 → 달력에서 날짜 확인

## 설정 순서

### 1. Supabase에 DB 만들기
1. https://supabase.com 가입 → **New project** 생성

```js
window.APP_CONFIG = {
  SUPABASE_URL: "https://abcdxyz.supabase.co",
  SUPABASE_ANON_KEY: "eyJhbGciOi...",
};
```
> `anon` 키는 공개돼도 되는 키입니다. `service_role` 키는 절대 넣지 마세요.

1. GitHub에서 새 저장소 생성 (예: `plate-reservation`)

   ```bash
   git init
   git add .
   git commit -m "차량 예약 조회 페이지"
   git branch -M main
   git remote add origin https://github.com/<아이디>/plate-reservation.git
   ```

## 알아둘 점

- **인식 방식**: 사선 촬영에 대비해 아래 순서로 읽습니다.
  1. 화면 **전체**에서 흰(또는 노란) 번호판 바탕 + 글자 줄무늬가 있는 사각형을 찾고(멀리 있어 작게 보여도), 그 부분만 **원본 해상도로 확대해 정면처럼 펴서(원근 보정)** 흑백으로 또렷하게 만든 뒤 읽기
     (사진 인식은 흑백·원본·절반 크기 세 번 읽어 다수결)
     · 번호판 바탕이 그릴(제네시스 등 큰 크롬 그릴)·범퍼와 붙어 흰 사각형으로 안 보일 때는 **글자 줄**(높이가 비슷한 글자 6~10개가 가로로 나란한 것)로 번호판을 찾습니다. 그릴 구멍처럼 똑같이 반복되는 무늬는 제외합니다.
  2. 번호판을 못 찾으면 사다리꼴·가로 늘이기·회전 보정을 프레임마다 바꿔 가며 읽기
  3. 번호판에 쓰이는 숫자·한글만 읽도록 제한하고, 여러 번 같은 번호가 나와야 확정
  4. 저장된 예약과 한 글자만 다르면 **"혹시 이 차량인가요?"** 버튼으로 한 번에 다시 확인
- **인식 정확도**: 무료 OCR이라 역광·야간·심한 오염 번호판은 틀릴 수 있습니다. 카메라 상태 표시줄에 `원근 보정`이 뜨면 번호판을 찾아 편 것입니다. 정확도가 더 필요하면 전용 번호판 인식 API(예: Plate Recognizer)로 `scanFrame` 부분만 교체하면 됩니다.
- **번호판 종류**: 긴 흰 번호판(한 줄), 짧은 흰 번호판(335×155, 한 줄), 예전 **두 줄 번호판**(녹색·노란색, "서울 12 / 가 3456")을 모두 찾습니다. 두 줄 번호판은 위아래 줄을 나눠 읽고, 녹색 번호판(흰 글자)은 밝기를 뒤집어 읽습니다. 지역명까지 읽히면 "서울12가3456"으로 나오며, 지역명 없이 등록된 예약(12가3456)과 같은 차량으로 판정합니다.
- 번호판을 못 찾았을 때 예전 방식으로만 읽은 번호는 두 가지 이상 보정에서 같게 나와야 인정합니다(번호를 지어내지 않도록).
- **보안**: 예약·정기 차량 데이터는 직원 명단에 있는 로그인 계정만 읽을 수 있습니다. 신청 페이지는 신청·남은 자리·본인 예약 조회/취소만 할 수 있고, 이름·연락처는 관리자(Supabase 대시보드)만 볼 수 있습니다.
- **시간 기준**: 신호등은 페이지를 연 기기의 현재 시각으로 판정합니다. 확인용 기기의 시계가 한국 시간으로 맞는지 확인하세요.
- 지원 번호 형식: `12가3456`, `123가4567`, `서울12가3456`
